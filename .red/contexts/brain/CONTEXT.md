# RedSkills Brain

The `brain` context names the project-local knowledge repository language for
RedSkills: artifact kinds, graph connections, search/synthesis semantics,
and the boundary between Brain (human knowledge) and Memory (operational
work facts).

## Language

**Brain store**:
The local RedDB knowledge repository at `.red/brain/brain.rdb`, owned by the
`brain` plugin; persists typed artifacts, graph connections, and search
rankings. Multi-folder organization supports walk-up resolution from child
projects to an umbrella Brain root.
_Avoid_: knowledge base, graph database, semantic store

**Artifact**:
A single typed unit of knowledge persisted in the **Brain store**: a person,
decision, question, note, idea, concept, playbook, meeting record, reference,
pattern, event, claim, rule, pillar, task, meeting, or source. Kind determines
ranking and relationship constraints.
_Avoid_: node, knowledge item, entry

**Artifact kind**:
The type classifier of an **Artifact** — one of thirteen canonical kinds:
`person`, `organization`, `decision`, `question`, `note`, `idea`, `concept`,
`playbook`, `meeting`, `source`, `pattern`, `event`, `claim`, `rule`, `pillar`,
`task`. Routing artifacts by kind is mandatory; inventing kinds is forbidden.
_Avoid_: vertex type, category, tag

**Brain-vs-Memory boundary**:
The decision rule for routing new knowledge: if the content is personal context,
identity, preferences, decisions, or long-lived organizational knowledge,
capture it to **Brain**. If it is a short operational work fact (gotcha,
why-note, code insight, validation evidence), route to **Memory** instead.
Brain is for human knowledge; Memory is for making agents work better.
_Avoid_: brain is for everything, memory is secondary

**Graph connection**:
A typed relationship between two **Artifacts** in the **Brain store** — one of:
`references`, `depends_on`, `contradicts`, `informs`, `elaborates`, `related`,
or custom edges. Connections are bidirectional and rank in hybrid search.
_Avoid_: edge, link, relation (use these for the technical substrate; use connection for the semantic model)

**Brain search**:
Deterministic hybrid ranking over **Artifacts** in the **Brain store** using
lexical title/content matches, tag matches, **Artifact kind** matches, and
**Graph connections**; each result carries a `score_breakdown` showing per-signal
contributions. Vector embeddings are reserved in the contract but not required
for the MVP.
_Avoid_: vector search, semantic search (those are future enhancements, not the current model)

**Brain think**:
A synthesis operation that ranks **Brain search** hits into a cited answer,
returning the artifacts plus stable **citations**, a deterministic `confidence`
label, and a `missing_evidence` list so Brain can state when it lacks evidence
instead of fabricating certainty. Citations point back to artifact kind, id,
score signals, excerpt, and captured provenance (source path, session, agent).
_Avoid_: retrieval-augmented generation, question-answering

**Brain capture**:
The operation to save a new **Artifact** to the **Brain store**, selecting an
**Artifact kind**, writing a title, and declaring tags if the content belongs to
a topic cluster. Routes user input through `/brain:capture` or the CLI `brain
capture` command.
_Avoid_: ingest, save, store (these are internal; the user verb is capture)

**Brain-vs-Memory routing**:
The boundary rule enforced by `/brain:capture` and `/memory:store`: content
about the person, identity, preferences, decisions, plans, relationships, or
organizational knowledge goes to Brain. Content about engineering decisions,
code gotchas, why-notes, or validation evidence goes to Memory. The BRAIN_VS_MEMORY
reference doc clarifies edge cases.
_Avoid_: implicit routing, same-store everything

**Brain root resolution**:
The walk-up logic for locating the **Brain store**: prefers explicit overrides
(env var `RED_BRAIN_ROOT` or `.red/config.yaml` `plugins.brain.rootDir`), then
walks up from the current directory until finding a real `.red/brain/` directory
or a `.red/brain.root` marker, then falls back to the nearest ancestor `.red/`
directory for compatibility. Supports multi-folder organizations with an umbrella
Brain.
_Avoid_: hard-coded paths, cwd assumption

**Brain dashboard**:
A self-contained HTML daily-driver overview of Brain with KpiQuery-backed event
metrics, recent decisions, recent typed connections, and summary scores; not a
node-link graph, and independent of the Memory Workbench. Generated by `brain
dashboard --out file.html` or `--serve --port 4738` for loopback.
_Avoid_: graph visualization, workbench

**Brain artifact kind vocabulary**:
The exhaustive canonical set of **Artifact kind** classifiers: `person`,
`organization`, `decision`, `question`, `note`, `idea`, `concept`, `playbook`,
`meeting`, `source`, `pattern`, `event`, `claim`, `rule`, `pillar`, `task`.
_Avoid_: inventing kinds outside this list

**Personal facts**:
Knowledge about people, identities, preferences, relationships, biographical
context, and durable human context the user wants available later. These belong
in **Brain**, not Memory; route via `/brain:capture`.
_Avoid_: routing to Memory, operational facts

**Red Brain MCP**:
The machine control protocol surface for the Brain plugin, exposing `brain_capture`,
`brain_search`, `brain_think`, and `brain_act` tools for agent-driven Brain
operations. Consumed by Claude Code and Codex via fetch + fetch-registry.
_Avoid_: internal Hermes bridge, raw database API
